# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 2's requirements (INFRA-03, ADMIN-01–06) are mostly infrastructure and configuration, not new visual surfaces. There are exactly two UI surfaces this phase touches:

1. **Sveltia CMS admin panel** (`/admin`) — a pre-built, CDN-loaded third-party UI. This project does **not** restyle or theme it this phase (no CSS override found or scoped in 02-RESEARCH.md). The only things this project controls are the *content* of `admin/config.yml`: collection labels, field labels, hints, and validation-error copy. Those are locked below in the Copywriting Contract, sourced verbatim from 02-RESEARCH.md's verified patterns so the planner does not re-invent them.
2. **The assistant's cheat-sheet (ADMIN-06)** — a genuinely new, brand-owned visual artifact. This UI-SPEC treats it as a one-page Astro page built from the exact same design tokens Phase 1 already locked (`src/styles/global.css`), rather than a new tool or export pipeline, to keep the $0/month constraint intact.

Everything below inherits Phase 1's design system (`01-UI-SPEC.md`, `src/styles/global.css`) unchanged — no new colors, type sizes, weights, or spacing tokens are introduced this phase.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — the cheat-sheet page is a hand-built Astro component reusing Phase 1's Tailwind v4 `@theme` tokens (`src/styles/global.css`); the CMS admin panel is Sveltia's own pre-built UI, loaded via CDN `<script>`, and is **not restyled** this phase |
| Icon library | Lucide (unchanged), inlined as static SVG — used only for the cheat-sheet's illustrations/callout icons. Sveltia's admin UI ships its own bundled icon set, not overridden. |
| Font | Lora (headings) + Inter (body), self-hosted via `@fontsource` (unchanged) — applies to the cheat-sheet page only. Sveltia's admin UI renders in its own default font stack, not overridden this phase. |

**shadcn gate — skipped, not blocked (carried forward from 01-UI-SPEC.md, unchanged reasoning).** No React/Vite component framework is introduced this phase; the site remains a zero-JS-by-default Astro static build. Sveltia CMS is a pre-built, CDN-loaded admin tool, not a component library this project assembles pages from — the shadcn gate does not apply to it. The one new page (the cheat-sheet) is a plain Astro/Tailwind component, consistent with Phase 1's precedent.

**Cheat-sheet delivery decision (Claude's discretion — flagged for confirmation, no CONTEXT.md exists to pre-answer this):** Built as a single Astro page at `/publishing-guide`, marked `<meta name="robots" content="noindex" />` (same pattern as `admin/index.html`), styled with the Phase 1 brand tokens, and designed to print cleanly to one Letter/A4 page (`@media print` rules hiding site nav/footer chrome). The developer prints or exports it to PDF once and hands the physical/PDF copy to the assistant — this avoids adding a new export tool, a design app subscription, or a manual off-repo document that can drift from the actual CMS UI. If the owner prefers a Google Doc / Canva handout instead, this page can still serve as the content source of truth; only the output format changes.

## Spacing Scale

Inherited from Phase 1 (`01-UI-SPEC.md`) unchanged — declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (cheat-sheet caption-to-screenshot gap) |
| md | 16px | Default element spacing (cheat-sheet paragraph gaps) |
| lg | 24px | Section padding (cheat-sheet section breaks) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used on the one-page cheat-sheet — reserved for future pages) |

Exceptions: **44px minimum touch target**, inherited from Phase 1, applies to any interactive element on the cheat-sheet page (e.g., a "Print this page" button, if added). Sveltia's own admin-panel touch targets are outside this project's control and are not verified against this rule.

## Typography

Inherited from Phase 1 (`01-UI-SPEC.md`) unchanged — exactly 4 sizes, exactly 2 weights, applies to the cheat-sheet page only:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (Inter) | 400 | 1.5 |
| Label | 14px (Inter) | 600 | 1.4 |
| Heading | 24px (Lora) | 600 | 1.2 |
| Display | 36px (Lora) | 600 | 1.15 |

Usage on the cheat-sheet: Display for the page title ("Publishing a New Home" or similar), Heading for the 3 section breaks (photo pre-resizing / publish-and-verify loop / troubleshooting), Body for instructional prose, Label for numbered-step captions under screenshots. Do not introduce a smaller caption size — 14px Label is the floor, matching Phase 1's accessibility floor (DESIGN-04 carries forward as a general project standard even though this phase's own requirement set doesn't restate it).

Sveltia CMS's admin UI renders in its own default type scale — not overridden, not part of this contract.

## Color

Inherited from Phase 1 (`01-UI-SPEC.md`) unchanged. Applies to the cheat-sheet page only — Sveltia's admin UI uses its own default theme, not restyled this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFDF7` (warm cream) | Cheat-sheet page background |
| Secondary (30%) | `#FBF4E4` (deeper warm cream) | Screenshot frames, numbered-step callout boxes |
| Accent (10%) | `#FFD053`, hover `#EDB52F` | "Tip" callout box fills only — nothing else on this page |
| Destructive | `#B3261E` | "If something looks wrong" troubleshooting section header/icon only |

Accent reserved for: **"Tip" callout boxes on the cheat-sheet** (e.g., the photo pre-resize reminder). Nothing else — body text, screenshots, and section headings stay on ink/cream, consistent with Phase 1's rule that accent never carries text on cream.

Destructive reserved for: **the troubleshooting section's header and warning icon only** — this is the phase this token (pre-declared but unused in Phase 1) first gets used.

### Field Validation Messages (locked)

| Field | Pattern rejection message |
|-------|---------------------------|
| `slug` (properties, blog) | "Lowercase letters, numbers, and single hyphens only (e.g. 614-e-marengo-st)" |

These are the assistant's **first line of defense** (CMS blocks bad input before a broken commit lands) — see 02-RESEARCH.md Pitfall 2. They must appear character-for-character as the CMS's inline validation copy since the cheat-sheet references them.

|-----------|------|
