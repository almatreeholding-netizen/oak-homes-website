Write `scripts/extract-mockup-photos.mjs` and run it once. Register it as an npm script named
`extract:photos` so re-running it is documented rather than folklore.

**Parse per property, not globally.** The mockup holds a `window.PROPERTIES` array with exactly two
entries, each containing a `photos` array of `data:image/jpeg;base64,` strings. A single global regex
over the whole file would produce one flat list of eleven images with no property boundary — the risk
RESEARCH.md records as assumption A3. Instead, locate each property object by its `address` value
(`614 E Marengo St`, then `2734 Brown Street`), and extract only the base64 strings inside that
object's own `photos` array. Assert the counts before writing anything: Marengo must yield exactly 6
and Brown Street exactly 5. If either count differs, fail loudly and write nothing — a silent
miscount would mis-assign photos between two homes, and mis-assigned real-estate photos are worse
than no photos.

**Resize before writing — and use a box constraint, not a width constraint.** Decode each base64
payload to a buffer and pipe it through sharp with exactly:

`.resize({ width: 2000, height: 2000, fit: 'inside', withoutEnlargement: true })`

All four options are load-bearing. `width` alone — the shape the RESEARCH.md sketch shows, which
this instruction deliberately supersedes — constrains only the horizontal axis: a portrait source at
1500×3000 satisfies it untouched and lands in permanent git history at a 3000px longest edge, failing
the constraint this plan claims to enforce. `height` with `fit: 'inside'` makes it a box both axes
must fit within while the aspect ratio is preserved, which is what "longest edge at most 2000px"
actually means. `withoutEnlargement` keeps an image already smaller than the box at its native size
rather than upscaling it into blur. Re-encode as JPEG at quality 85. Do not crop and do not force a
fixed height.

**Assert before writing, because this write is irreversible.** After encoding and before `toFile`,
read the encoded buffer's own metadata back and throw if `Math.max(width, height) > 2000`, naming the
file and its dimensions. Git retains every committed blob forever, so an oversized photo caught by a
post-hoc acceptance check has already cost a history rewrite; caught by this assertion it costs
nothing. The acceptance criteria below still verify the written files independently — the assertion
is the guard, the criterion is the proof, and neither replaces the other.

Write to `public/uploads/properties/<slug>/photo-01.jpg` through `photo-06.jpg`, zero-padded and
numbered in the order the mockup lists them, because the first photo is the cover (PROP-01).

Use sharp exclusively for this. ImageMagick is not installed on this machine, and Windows ships its
own unrelated `convert.exe` that shadows the name — a command that appears to succeed while producing
no image.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mockup HTML → extraction script → committed image files | Base64 payloads decoded and written to disk, then committed permanently. Developer-authored source, but the write is irreversible once committed. |
| content file → build | Property frontmatter validated by Zod before rendering. Phase 1's only input-validation surface (ASVS V5). |
| property description copy → public HTML | Marketing copy about housing, which carries Fair Housing advertising obligations that ordinary product copy does not. |
| built HTML → visitor browser | Static output plus one client-side island (the lightbox). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-12 | Information Disclosure | Oversized or unintended image blobs entering permanent git history | high | mitigate | The extraction script resizes with a **two-axis box constraint** (`width: 2000, height: 2000, fit: 'inside', withoutEnlargement: true`) — not the width-only recipe, which leaves portrait sources oversized — and re-reads each encoded buffer's metadata, throwing before `toFile` if the longest edge exceeds 2000. It writes only into `public/uploads/properties/<slug>/`. Acceptance criteria then verify every written file's dimensions with sharp metadata and a 1 MB ceiling, and require deliberately lowering the threshold to prove the guard actually fires. Guard first, proof second: this is the phase's one irreversible write. |
| T-01-13 | Tampering | Photos mis-assigned between the two homes by a global regex crossing property boundaries | high | mitigate | The script parses each property object individually, keyed on its `address` value, and asserts the exact per-home counts (6 and 5) before writing anything. A count mismatch fails loudly and writes nothing. Mis-assigned listing photos are a material misrepresentation, not a cosmetic bug. |
| T-01-14 | Tampering | Property copy acquiring Fair-Housing-steering language | high | mitigate | Descriptions are ported from the mockup's existing `desc` text, which describes homes rather than occupants, and the task action forbids adding who-this-suits framing. Carried as a flagged prohibition in `must_haves.prohibitions` for judgment review. |
| T-01-15 | Tampering | Sold or Pending status rendering ambiguously enough to read as available | high | mitigate | D-09's CTA replacement is asserted by acceptance criteria that flip the status, rebuild, and require both the presence of the replacement CTA and the absence of the Inquire CTA. Status is also carried as badge text, never by colour alone. |
| T-01-16 | Tampering | Malformed property frontmatter reaching the built site | medium | mitigate | ASVS V5: the Zod schema from plan 01-02 validates both entries; `npm run build` failing is the gate. |
| T-01-17 | Information Disclosure | Metadata (EXIF, GPS coordinates) embedded in extracted photos | low | mitigate | sharp's re-encode pipeline does not carry EXIF through by default, so the JPEG re-encode strips it. The source images are base64 payloads already stripped by the mockup's own export, so no location data is expected in the first place. |
| T-01-18 | Elevation of Privilege | The lightbox island as a client-side script surface | low | accept | Hand-rolled, dependency-free, operating only on build-time-known image paths from validated content. No user input, no network calls, no dynamic evaluation. |

rather than from a visitor.
