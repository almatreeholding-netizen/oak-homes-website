  <action>
Audit the assembled site against WCAG 2.1 AA basics and the responsive contract, and fix what fails.
Prefer fixing at the token or component level over patching individual pages — a contrast failure on
one badge is a token problem, not a page problem.

**Images.** Confirm every image across every built page carries an alt attribute. Meaningful images
describe what they show; a property photo's alt says what the photo depicts, not the filename and not
a second copy of the address that the adjacent heading already announces. Decorative marks use an
empty alt paired with `aria-hidden` so a screen reader skips them rather than announcing the brand
twice. An image with no alt attribute at all is the failure this checks for — an empty alt is only
correct when it is deliberate and paired.

**Contrast.** Measure actual rendered foreground-on-background pairs, not intentions: body copy and
label text need 4.5:1, and text at 24px and above needs 3:1. Check the three badge variants against
their own fills, the price figures against both cream surfaces, button text against the accent fill,
and the footer text against the ink footer. The accent is a fill colour only — if it has become text
on cream anywhere, that is a failure to fix, because it lands near 2:1. Price figures use the
price-gold token, which the UI-SPEC records at 3.3:1 on both creams and therefore passing for the
24px figures but not for anything smaller.

**Keyboard operation.** Tab through every page start to finish. Every interactive element must be
reachable in an order that matches the visual layout, carry a clearly visible focus indicator, and
activate with Enter (and Space, for anything behaving as a button). The two client-side islands need
particular care: both the mobile nav drawer and the gallery lightbox must trap focus while open,
close on Escape, and return focus to the element that opened them. A drawer or lightbox that leaves
focus behind on the page underneath is the most common failure here.

Add a skip-to-content link as the first focusable element on the page, targeting the main landmark.

**Semantics and landmarks.** Every page needs exactly one h1 and a heading order that descends
without skipping a level. Confirm the nav, main, and footer landmarks are real elements rather than
styled divs. Confirm the document language and character encoding are declared, and that the em
dashes, apostrophes, and curly quotes in the ported legal copy survive the build as their exact
source characters rather than as replacement characters or escapes — that copy is legally refined and
a mangled character in it is a real defect.

Confirm status is never carried by colour alone: each badge states its status as text.

**Responsive.** Check every page at 320px, 375px, 768px, and 1280px. Nothing may scroll horizontally,
clip, or overlap. Give particular attention to the longest real address on a card at 375px, the
seven nav labels at exactly 768px (if they do not fit on one line, raise the hamburger breakpoint
rather than shrinking the type below the four-size scale), and the gallery lightbox controls at
320px. Confirm the 44px minimum hit area holds at the narrowest width for the four elements the
UI-SPEC names: the phone CTA, the nav hamburger, the lightbox arrows, and the Inquire button. Confirm
exactly one phone CTA is visible at any given width — the header CTA and any persistent mobile phone
element must not both appear where their media queries meet.

Fix every failure found. Where a fix would require a fifth font size or a colour outside the token
set, change the layout or spacing instead — the type scale and the token set are the contract.
