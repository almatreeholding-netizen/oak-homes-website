## Executor shell contract — read before running any `<verify>` block

**The executor session's shell on this machine is Windows PowerShell 5.1**, which is not POSIX:
`&&` is a parse error and `grep`, `find`, `wc`, and `test` do not exist. A Bash verify block there
fails to *parse* rather than to *pass*, which reads as noise and invites verification to be skipped.

Every `<automated>` block in this plan is therefore exactly one command:

```
node scripts/verify/checks.mjs <check-id>
```

`scripts/verify/checks.mjs` was created in plan 01-01 Task 2; its full authoring rules are in that
plan's `<shell_contract>`. Node built-ins only, no shelling out to POSIX utilities, `spawnSync` with
an argv array (`npm.cmd` on win32), unknown check id exits non-zero, and a check that cannot run its
assertion fails loudly rather than passing.

This plan registers three checks: `homepage` (Task 1), `content-pages` (Task 2), and `learn-section`
(Task 3). `content-pages` carries the phase's most delicate assertion — the verbatim-transcription
comparison — and the normalisation pipeline it must implement is specified in Task 2's acceptance
criteria, not left to the check author's discretion.
</shell_contract>
